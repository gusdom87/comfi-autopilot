# Decision Ledger

A before/during record for the Meta Global AI Developer Hackathon build (Oct 26 to Nov 4, 2026).

## Rules of this ledger

- Every material decision gets a dated entry: what was decided, why, and what it rules out.
- "Before" entries describe pre-event background (pilot, labeled data, operator experience). They are never presented as hackathon-built work.
- "During" entries describe work built inside the event window only. The demo highlights during-entries only.

## Entries

- 2026-10-26 (during): Day 0 scaffold committed and pushed: package layout, fail-safe Meta API client (any failure returns no-decision; callers fall back to Confirm), tiering policy entry points, eval/sandbox/metrics skeletons, architecture notes. Fail-safe tests pass (2).
- 2026-10-26 (during): Meta Model API facts pinned in docs/API-NOTES.md: base https://api.meta.ai/v1, POST /responses, model IDs muse-spark-1.3 and muse-wonder-1.0 with published prices. API key creation is gated on a payment method being on file, so the first live call waits on both the $150 credits posting and the card decision.

The redacted set is the eval dataset; the mapping stays private and the dataset is not published.
- 2026-10-26 (during): Four build specs written for Claude Code: core port, eval harness, outcome metrics, sandbox page. Build order follows the Fable plan.

Builder note: the Mac mini's terminal is not reachable through Milo's device controls (terminal apps are excluded from Mac control), so Milo is building directly in this repo; the four specs remain the build contract.
- 2026-10-26 (during): Eval ground truth constructed and documented (docs/DATASET.md): pilot report-card export's ground_truth field was empty; labels derive from the operator's hand verdicts joined on message ID (107 of 107 matched). 89 labeled messages (Confirm 33, Act 31, Ignore 25); 18 wrong/unsure held out for the operator to re-label. Category-to-label mapping is written down in the open so judges can argue with it.
- 2026-10-26 (during): Eval harness, sandbox page, and outcome-metrics script built to specs 02-04 with mocked clients and fixtures; 11 tests passing. Sandbox smoke-tested live: with no API key it serves the page and the triage endpoint returns the Confirm fail-safe, as designed. Everything that does not need the Meta API is now built; the remaining gate is credits posting plus the card and key, expected by Oct 28.
- 2026-10-27 (during): First live Meta Model API calls. The $150 free credits posted (verified on the Billing page), a payment method was added, and the API key reached the build through a secure hand-off (never in chat, never in git; .env is gitignored). scripts/first_call_check.py sent one staged lockout message to each tier: muse-spark-1.3 answered Act at 0.99 confidence in 11.2 s ($0.0025); muse-wonder-1.0 answered Act at 0.98 in 4.0 s ($0.0076). Both correct. This also settles availability: Wonder answers on this US account. Next: the three-arm eval ablation on the 89-message redacted set.
- 2026-10-27 (during): First eval ablation on the 89-message set (6 few-shot examples, n=83 scored per arm). spark_only: 73.5% overall, 76.6% decisive, Act recall 50% (errors skew to Confirm). wonder_only: best answered-row quality (88.5% decisive, 88.6% high-confidence) but 27 of 83 calls timed out at the client's 20 s timeout and fell back to fail-safe Confirm, so its 62.7% overall measures latency, not judgment. escalate: 68.7% overall; only 4 of 83 messages escalated because Spark is overconfident (70 of 83 confidences at 0.85+, high-confidence accuracy no better than overall). Total spend $3.08. Fix chosen with the operator: raise request_timeout_secs 20 -> 75 and re-run the Wonder and escalate arms before any prompt tuning. Scorecards live in eval/runs/ (uncommitted, under review).
- 2026-10-27 (during): Timeout rerun at 75 s, sequential (a first parallel attempt was contaminated: running both arms against one account produced fast transport errors the client reports identically to timeouts, 29 and 48 fail-safe rows; those two run dirs are not results). wonder_only at 75 s: zero timeouts, overall 73.5%, decisive 81.4% (n=43), high-confidence 86.0%, Act recall 46.4% (13/28), $2.82. escalate at 75 s: zero fail-safes, all 5 escalations completed (3 correct), overall 69.9%, decisive 72.9%, $1.07, cheapest per correct decisive call ($0.030 vs Wonder-only $0.081). Conclusion: latency is solved; the remaining Act weakness is judgment in the shared prompt, not the models. Both tiers downgrade roughly half of true-Act messages to Confirm. Next lever is prompt tuning for urgent-message recall, then a Spark-first re-test. No arm yet meets the ladder's P2 thresholds, so Jev correctly stays at approve-first.
